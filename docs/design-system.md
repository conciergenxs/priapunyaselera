# PPS design system

Audit of the approved homepage (`index.html`, `css/tokens.css`, `css/main.css`,
`js/main.js`). These four files are the source of truth and are **not edited**
when adding pages. New pages load them as-is and add `css/pages.css` on top.

## Stack and conventions

- Static HTML + CSS + vanilla JS. No framework or build step.
- One stylesheet per layer: `tokens.css` (custom properties), `main.css`
  (base, shared components, homepage sections), `pages.css` (components used
  only by the inner pages).
- BEM-style class names (`block__element--modifier`), one section per
  `<section class="section … theme-dark|theme-light">`.
- Each page lives at `/<route>/index.html` so the homepage's root-relative
  links (`/event`, `/artikel`, `/loyalty`, `/merch`, `/exclusive-pass`) resolve
  without changes. Inner pages use root-relative asset paths (`/assets/…`).
- Images: originals in `assets/<area>/`, web copies in `assets/<area>/optimized/`
  generated by `scripts/optimize_images.py` (WebP, several widths).
- Copy is Indonesian, casual "lo/gue" voice.

## Layout and spacing

- Container: `.container` = `min(100% − 2 × gutter, 80rem)`; gutter 20 → 64px.
- Section padding: `--section-pad-y` 80 → 128px. Header → content gap 48 → 64px.
  Headline → copy 24px. Copy → actions 32px. Grid gap 24px.
- Spacing scale `--space-1 … --space-12` (4px base: 4, 8, 12, 16, 24, 32, 40, 48, 64, 80, 96, 128).
- `.split`: headline left, copy + action right (two columns from 1280px).
- Breakpoints: 40em (640), 48em (768), 64em (1024), 80em (1280).

## Header (`.site-header`, `js/main.js`)

Fixed. On desktop a dark glass pill (72% ink, 18px blur, gold stroke) wraps only
the centred nav at the top of the page and widens to the container edges over
the first 200px of scroll (`--p` 0 → 1, eased in a rAF loop). Logo left, MASUK
right; when expanded MASUK fills logo-gold with ink text. Below 1024px the bar is
always full width and the nav collapses into a glass panel behind a toggle.
An inline script after the header sets `--nav-w` before first paint.

## Buttons (`.btn`)

Pill (`--radius-pill`), 52px tall (44px `.btn--sm`), 40px side padding,
216px min width, 14px/700 uppercase. Transitions 180ms on background, border,
colour and transform; 1px press offset.
- `.btn--primary`: burgundy, white text; brighter on hover, darker when pressed.
- `.btn--secondary`: transparent, 1px logo-gold border, white text; fills gold
  with ink text on hover. Designed for dark backgrounds.
- `.actions`: buttons side by side at equal width (≥640px), stacked full width
  on phones.

## Cards and surfaces

- `.merch-card`: photo fills the card, bottom fade for text, white title,
  logo-gold points, gold stroke, 14px radius (`--radius-card`), soft shadow.
- FAQ rows: 1px light line, 14px radius, translucent ink fill, gold on open.
- Textures: `hero` photo (dark), `showcase` cream wall, `faq` red satin. Dark
  photo areas always get an ink scrim for legibility.

## Footer

Hairline divider, brand block left (logo 64px, name, two-line description),
3 × 2 link grid on the right (8rem columns), bottom row: copyright left, legal
links right. Stacks below 1024px.

## Pages and routes

| Sitemap page | Route | Sections |
| --- | --- | --- |
| Homepage | `/` | Hero (Lihat Hadiah only), Merchandise preview (cards open the item on Loyalty), FAQ, CTA (hidden), Footer |
| Event | `/event/` | Hero, Event list (filter + register), App download banner |
| Article | `/artikel/` | Hero, Article previews (6 cards from `js/article-data.js`) |
| Article detail | `/artikel/baca/?id=<id>` | Back button, article, Baca Artikel Lainnya, sticky reading bar (points once per article, `ARTICLE_POINTS`) |
| Loyalty Program | `/loyalty/` | Hero, Earn points, Guild Merch preview, Exclusive Pass preview, How to redeem |
| Login | `/masuk/?next=<path>` | Standalone (no header/footer): logo, username or WhatsApp number + password, link to Register |
| Register | `/daftar/?next=<path>` | Standalone: logo, username, WhatsApp number, password, link to Login |
| Profile | `/profil/` | Dummy profile (no login): photo hero (name, username, phone) + menu: Passport (bottom sheet with the supplied QR, `assets/qr.png`), Merchandise (→ `/merch/`), Edit Profile, Ubah Password (dialogs), Logout |
| Loyalty: shipping | `/loyalty/tukar/?item=<id>` | No hero, solid header: white form card + merch summary, final confirmation |
| Loyalty: success | `/loyalty/tukar/berhasil/?order=<ref>` | No hero: white card with order number (copy), item, points, Lacak Pesanan |
| Pesanan Merchandise | `/loyalty/pesanan/` (`?status=<tab>`), `?order=<ref>` | No hero: status tabs (Semua, Menunggu Diproses, Diproses, Dikirim, Selesai) + order cards; an order's detail: status timeline, shipping info. Profile → Merchandise links here |
| Guild Merch | `/merch/` | Main banner, Item detail, Cart, Activity, Transaction |
| Guild Exclusive Pass | `/exclusive-pass/` | Same structure as Guild Merch |

`/hadiah/` is a redirect stub (to Guild Merch) that keeps the homepage's link
working. Replace it with a server redirect in production. Root-relative paths mean the site must be
served from the domain root (locally: `python3 scripts/serve.py`, which sends
`Cache-Control: no-cache` so browsers never keep running outdated JS modules).
Module URLs aren't fingerprinted, so a production host should also revalidate
`/js/` (or add a build step that hashes filenames).

## Scripts and demo data

- `js/main.js`: header (all pages). `js/app.js`: inner-page entry (ES module);
  loads `account.js`, then `shop.js`, `events.js`, `article-list.js`,
  `article-reader.js`, `profile.js` or `auth-page.js` when the page has the matching `data-*` root.
- `js/store.js`: the session plus one member record per account in
  `localStorage` (points, carts, transactions, activity, profile). Logged out,
  pages get a blank guest state that is never saved. There is no backend; swap
  these exports for API calls when one exists.

## Accounts and the login gate (prototype)

- `js/auth-boot.js` (classic script in every `<head>`): sets
  `<html data-auth="in|out">` before first paint so the header never flashes.
  Pages with `<meta name="pps-auth" content="required">` (article detail,
  Guild Merch, Exclusive Pass, the Loyalty shipping/success/tracking
  pages) send logged-out visitors to `/masuk/?next=<this page>`;
  `content="guest"` (Login, Register) sends signed-in members on to `next`.
- Header: logged out shows MASUK; signed in shows `.site-header__account`
  (outlined points link to Loyalty + round profile button that fills gold once
  the bar expands).
- `js/account.js` (every page): keeps the header and `[data-points-balance]`
  in step with the session, here and in other tabs. Anything marked
  `data-auth-required` is gated while logged out: the click goes to Login with
  `next` set to the link target, or to this page plus
  `?lanjut=<data-auth-action>` (`merch:<id>`, `pass:<id>`, `daftar:<event>`),
  which `redeem.js` / `events.js` resume after login. Browsing listings is
  never gated.
- `js/auth.js`: register, login (username or WhatsApp number), logout,
  `next` validation (same-site only, never Login/Register, so no loops).
- **Prototype bypass:** both forms only check that every field is filled in.
  Login with any username/number signs in (a known one reopens that account,
  an unknown one creates it); Register with an existing username signs in to
  it. Passwords are never checked or stored.
- **Limitations (mocked, no backend):** accounts, sessions and member data
  live only in this browser's `localStorage`. No real registration, password
  check, rate limiting, password reset, OTP/WhatsApp verification or
  cross-device login. New accounts start with a demo balance of 6,200 points.
  Replace with the PPS account service before launch.
- `js/catalog.js`: Guild Merch and Exclusive Pass items.
- `js/article-data.js`: the six articles and `ARTICLE_POINTS`; `js/article-list.js`
  renders cards, `js/article-reader.js` renders a detail page and tracks reading.
- Sample content (events, articles, passes, point rules, product specs, the
  demo member) is marked in the source and needs confirming before launch.

## Inner-page additions (`css/pages.css`)

Inner pages reuse everything above and add only: `.page-hero`, `.surface`
(charcoal card with gold stroke), chips, event rows, article cards and reader,
pass cards, steps, form fields, and the shop layout. The approved homepage
does not load `pages.css`.
